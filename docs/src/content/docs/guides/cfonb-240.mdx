CFONB 240 files hold batches of transfers: one record of 240 characters per line, its first two characters being the
record code.

## Reading a file

`Cfonb240Reader::parse()` takes the contents of the file and returns a list of
[`Transfer`](/reference/cfonb-240-objects/#transfer):

```php
use Silarhi\Cfonb\Banking\Transfer;
use Silarhi\Cfonb\Cfonb240Reader;

$reader = new Cfonb240Reader();

foreach ($reader->parse(file_get_contents('/path/to/cfonb240-file.txt')) as $transfer) {
    assert($transfer instanceof Transfer);
}
```

The same, with more fields:

```php
foreach ($reader->parse($content) as $transfer) {
    // Transfer header
    $header = $transfer->getHeader();
    echo "Transfer Date: " . $header->getPrevTransactionFileDate()->format('Y-m-d') . "\n";
    echo "Bank Code: " . $header->getRecipientBankCode1() . "\n";
    echo "Account: " . $header->getRecipientAccountNumber1() . "\n";

    // Transactions of the transfer
    foreach ($transfer->getTransactions() as $transaction) {
        echo "Transaction Date: " . $transaction->getSettlementDate()->format('Y-m-d') . "\n";
        echo "Amount: " . $transaction->getTransactionAmount() . "\n";
        echo "Recipient: " . $transaction->getRecipientName1() . "\n";
        echo "Reference: " . $transaction->getPresenterReference() . "\n";
    }

    // Transfer total
    $total = $transfer->getTotal();
    echo "Total Amount: " . $total->getTotalAmount() . "\n";
    echo "Sequence Number: " . $total->getSequenceNumber() . "\n";
}
```

## How transfers are built

- a header line (`31`) starts a new transfer.
- a transaction line (`34`) is added to the current transfer.
- a total line (`39`) is set on the current transfer, which is then added to the list and closed: the next transaction
  or total line needs a new header.
- an empty line is ignored; a line of spaces or tabs throws a `ParseException`.

So every transfer returned has a header and a total: `getHeader()` and `getTotal()` never throw on them. Any other order
throws a `ParseException`: a transaction or a total line outside a transfer (before the first header, or between a
total and the next header), a header line while a transfer is still open, a transfer still open at the end of the file:

```text
Unable to attach the transaction with sequence number 2: missing "31" header record before it
Unable to attach the total with sequence number 3: missing "31" header record before it
Unable to start a transfer with the "31" header record of sequence number 1: the previous transfer has no "39" total record
Unable to close the transfer of the "31" header record of sequence number 1: missing "39" total record at the end of the file
```

:::note[Since 6.5]
6.4 did not check this order: such records were attached to the wrong transfer, or dropped, instead of throwing. The
date checks below are new in 6.5 too.
:::

## Amounts

Transaction and total amounts are 12 digits in cents, read as floats with 2 decimals: `000000171200` is `1712.00`.
Unlike CFONB 120 amounts, they have no sign: they are never negative. `getTransactionAmount(true)` and
`getTotalAmount(true)` (since 6.6) give the exact amount as a decimal string, `"1712.00"`: store, add and compare these
instead of the floats. Without the argument, they return the float until 7.0.

The reader does not check that the total is the sum of the transactions: `$transfer->validate()` (since 6.6) does, and
that the total belongs to the account of the header. See
[checking the consistency of a file](/guides/troubleshooting/#checking-the-consistency-of-a-file).

## Dates and strict mode

Dates are typed `DateTimeInterface` and are `DateTimeImmutable` objects at midnight, read from `DDMMYY`, like the
[CFONB 120 dates](/guides/cfonb-120/#dates): a date that does not exist, such as `320420`, throws a `ParseException`.
`getInitialTransactionSettlementDate()` is `null` when blank or zero-filled (`000000`); the other dates are mandatory, and
`000000` there throws a `ParseException`.

`parse()` accepts the same `$strict` argument as `Cfonb120Reader::parse()`, but no CFONB 240 rule depends on it:
malformed lines and records out of order always throw a `ParseException`.

## Error handling

```php
use Silarhi\Cfonb\Cfonb240Reader;
use Silarhi\Cfonb\Exceptions\ParseException;

$reader = new Cfonb240Reader();

try {
    $content = file_get_contents('/path/to/cfonb240-file.txt');

    foreach ($reader->parse($content) as $transfer) {
        echo "Processing transfer from: " . $transfer->getHeader()->getRecipientBankCode1() . "\n";

        // Process transactions...
    }
} catch (ParseException $e) {
    echo "Failed to parse CFONB file: " . $e->getMessage() . "\n";
}
```

`HeaderUnavailableException` and `TotalUnavailableException` are only thrown by a `Transfer` built by hand, without
`setHeader()` or `setTotal()`: see [exceptions](/reference/exceptions/).
