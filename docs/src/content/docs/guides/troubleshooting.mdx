## Common parsing errors

The readers throw a `ParseException` on the first line they cannot parse. The message tells what failed:

:::caution[Upgrading to 6.5]
6.5 rejects files that 6.4 accepted: records out of order and zero-filled or out-of-range dates
throw since 6.5, in strict and non-strict mode alike, where 6.4 returned wrong data silently. The messages about the
order of the records (`missing "01" old balance`, `has no "07" new balance`, `missing "31" header`, `has no "39" total`)
and about dates are new in 6.5. Parse a sample of the files you receive before upgrading: see the
[changelog](https://github.com/silarhi/cfonb-parser/blob/6.x/CHANGELOG.md).
:::

| Message                                                                                                                                            | Cause                                                                                                                                                                          |
| -------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `Unable to find a parser for the line …: record code "…", … characters`                                                                            | The line is not 120 (CFONB 120) or 240 (CFONB 240) characters long, or its record code is unknown: CFONB 120 supports `01`, `04`, `05` and `07`, CFONB 240 `31`, `34` and `39` |
| `Regex does not match the line: the field "…" at position … is invalid`                                                                            | The field holds unexpected characters: letters in a numeric field, a date or an amount, an invalid sign character                                                              |
| `The value of key "…" is not a string`                                                                                                             | A required field is blank, e.g. the currency of a balance, or the reference of an operation in strict mode                                                                     |
| `The value of key "…" is not numeric`                                                                                                              | A numeric field is blank, e.g. the number of decimals of an amount                                                                                                             |
| `Unable to attach a detail for operation with code …`                                                                                              | A `05` detail line with no `04` operation before it in its statement                                                                                                           |
| `Unable to attach the operation with code … dated …: missing "01" old balance record before it`                                                    | A `04` operation line outside a statement: before the first `01` old balance, or after a `07` new balance without a new `01` old balance                                       |
| `Unable to close a statement with the "07" new balance of account … dated …: missing "01" old balance record before it`                            | A `07` new balance line with no open statement: before the first `01` old balance, or right after another `07` new balance                                                     |
| `Unable to open a statement with the "01" old balance of account … dated …: the statement of account … opened on … has no "07" new balance record` | A `01` old balance line while a statement is still open: the `07` new balance of that statement is missing                                                                     |
| `Unable to close the statement of account … opened on …: missing "07" new balance record at the end of the file`                                   | The last statement has no `07` new balance: the file is likely truncated                                                                                                       |
| `Unable to parse date "…"`                                                                                                                         | A date that does not exist: day `00` or `32`, month `00` or `13`, 31 April, 29 February of a non-leap year                                                                     |
| `Unable to parse date "000000": the date is zero-filled (empty), but this field is mandatory`                                                      | A mandatory date written as zeros, e.g. the value date of an operation: some banks write a date they do not have this way                                                      |
| `Unable to attach the transaction with sequence number …: missing "31" header record before it`                                                    | A `34` transaction line outside a transfer: before the first `31` header, or after a `39` total without a new `31` header                                                      |
| `Unable to attach the total with sequence number …: missing "31" header record before it`                                                          | A `39` total line outside a transfer: before the first `31` header, or after a `39` total without a new `31` header                                                            |
| `Unable to start a transfer with the "31" header record of sequence number …: the previous transfer has no "39" total record`                      | A `31` header line while a transfer is still open: the `39` total of that transfer is missing                                                                                  |
| `Unable to close the transfer of the "31" header record of sequence number …: missing "39" total record at the end of the file`                    | The last transfer has no `39` total: the file is likely truncated                                                                                                              |

:::note[Since 6.6]
The messages no longer hold the line that failed: it holds account numbers and labels, which do not belong in logs or
error pages. They give the line number, the record code and length, or the field and its position instead. The line
itself is still available with `$e->getRawContent()`, to debug a file: do not log it or show it as is.
:::

```php
use Silarhi\Cfonb\Cfonb120Reader;
use Silarhi\Cfonb\Exceptions\ParseException;

$reader = new Cfonb120Reader();

try {
    $statements = $reader->parse($content);
} catch (ParseException $e) {
    // Common issues:
    // - Invalid line length (should be 120 characters)
    // - Unknown record code (CFONB 120 supports 01, 04, 05 and 07)
    // - Malformed line format
    // - Invalid, out-of-range (e.g. day 32) or zero-filled date
    // - Records out of order (e.g. a missing "07" new balance)
    // - Invalid amount format

    echo "Parse error: " . $e->getMessage() . "\n";

    // The raw line that failed, kept out of the message: it holds account numbers
    $line = $e->getRawContent();

    // Non-strict mode only tolerates blank operation references,
    // any other error is still thrown
    $statements = $reader->parse($content, false);
}
```

Non-strict mode only tolerates blank operation references: see
[strict mode](/guides/cfonb-120/#strict-mode-default-vs-non-strict-mode).

## Checking the consistency of a file

The readers check each line and the order of the records, not the consistency of the file: an operation of another
account is added to the statement, and the closing balance is not compared with the opening balance and the operations.
`validate()` (since 6.6) checks it, on the statements or transfers you need to trust:

- `Statement::validate()`: the `07` new balance, the `04` operations and their `05` details belong to the account of the
  `01` old balance (same desk code, account number and currency; the bank code is only compared between the two
  balances, as some banks write another one on operations), and the new balance is the old balance plus the operations.
- `Transfer::validate()`: the `39` total belongs to the account of the `31` header (same bank code, counter code,
  account number and currency index), the `34` transactions have the currency index of the header, and the total is the
  sum of the transactions.

The amounts are added as integers in minor units, never as floats. The first check that fails throws a
`ValidationException`, a `ParseException`: `getCheck()` tells which one, a
[`ValidationCheck`](/reference/exceptions/#validationcheck). The message keeps the account numbers out.

## Line endings and trailing spaces

`\n`, `\r\n` and `\r` (classic Mac OS, since 6.5) line endings are read alike, as are files with no line breaks at
all, split every 120 (or 240) characters. Empty lines are ignored, but not a line of spaces or tabs: it throws
`Unable to find a parser for the line`.

<Example name="troubleshooting-line-endings" />

The trailing spaces of a line are part of its 120 or 240 characters: an editor, a transfer tool or a `trim()` removing
them makes the line too short. Normalize line endings with `str_replace(["\r\n", "\r"], "\n", $content)`, never with
`trim()` on each line.
